# Upgrade to Umbraco 19

From Umbraco Commerce `[18.0.0, 18.999.999)` (CMS 18) to Umbraco Commerce `19.0.0-beta.1` (CMS `19.0.0-beta1`, tag `release-19.0.0-beta1`).
Branch `v19/topic/cms-19-upgrade` → PR into `release/19.0.0`, cut from `main` (`e816c54`).

**Targets CMS release:** `release-19.0.0-beta1`, via Umbraco Commerce `19.0.0-beta.1` (MyGet `umbracoprereleases`, already in `NuGet.config`). The package's own version is `19.0.0-beta.1`.

The package depends on `Umbraco.Commerce.Core` and `Microsoft.Extensions.Http`, never on `Umbraco.Cms.*` directly, so CMS breaking changes reach it only through Commerce. Commerce's own v19 inventory (Core repo, `docs/upgrades/v19.md`) is the source for those. Same pattern as the Stripe provider's v19 upgrade.

## Follow-ups

- Live smoke with Shipmondo credentials before 19.0.0 final: a quote list for a DK→DK and a DK→SE parcel in DKK, checking rates show at checkout with the VAT split (live smoke pending; the unit tests can't run this).
- Fixed on `v19/topic/fix-quote-errors` (stacked PR): the HTTP status is now checked (failed calls log the status and body and return no rates), quotes without a currency are skipped, Test Mode uses the Shipmondo sandbox, and `ShimpondoPrice` is renamed `ShipmondoPrice` (old name `[Obsolete]`, removed in v21). The status and currency fixes are backported to 18.0.1 and 17.0.1; there Test Mode only gets a description saying it isn't used, since switching endpoints in a patch would stop rates for stores that left it ticked with live keys. Release note: `ShipmondoParcel.DeclaredValue` is now typed `ShipmondoPrice`.
- `DeclaredValue` is never set; `Quantity`/`Volume` serialise as `null` (pre-existing).
- Only the first package is quoted (pre-existing). Left as is: Commerce's default package factory makes one package per order, and quoting several means summing rates per service across packages, which is a design change.
- `NU1510`: `Microsoft.Extensions.Http` is part of the shared framework (`Microsoft.AspNetCore.App`) and the explicit reference can go (pre-existing on v18).
- Test project package versions (xunit 2.6.6, Test.Sdk 17.8.0, FluentAssertions 6.12.0) copy Stripe's; update the providers together later.
